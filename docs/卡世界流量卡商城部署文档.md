## 一、这是什么

卡世界流量卡商城的**成品部署包**（uni-app H5 构建产物，纯静态文件）。商城在售商品为三大运营商的大流量手机卡：低月租大流量、全国通用或本省专属，用户线上免费申请，运营商官方审核发货、激活后按套餐资费计费。

特点：

- **默认自带店铺**：内置卡世界「号卡办理中心」店铺（店铺码 `tnTzlcsG66`），部署完成打开即是该店铺的完整商城，商品、价格、库存、图片与卡世界平台实时同步。
- **零对接**：页面文件放你的服务器，商城前端会自动请求你自己域名下的 `/api` 接口，由你的 Nginx 按本文档给的现成配置转发到卡世界后端——复制一段配置即可，你不需要写一行代码。
- **零运营**：商品上下架、资费调整、订单受理、发货售后全部由卡世界平台统一处理，你的商城自动跟随，无需重新部署。
- **数据安全**：买家提交的办理信息直达卡世界订单系统，不经过部署方的服务器。

适用场景：想在自己域名下快速拥有一个流量卡商城做推广变现，不想写代码、不想管供货和售后。

## 四、部署步骤

整个部署只有一件事：**把静态文件放到你的域名下**。

### 4.1 获取部署包

部署包：`liuliangka-mall-dist-v3.zip`（约 21MB，卡世界线上商城的完整静态构建产物，已内置默认店铺 `tnTzlcsG66`）。

> GitHub 仓库地址：【发布后填入】

解压后是一堆静态文件（`index.html`、`static/`、`assets/`），全部上传到你的站点目录即可。

### 4.2 Nginx 部署（推荐）

把部署包文件上传到站点目录（如 `/www/wwwroot/mall`），站点配置参考（只需把域名和证书换成你的）：

```nginx
upstream ksj_mall_api { server ym.ksjhaoka.com:443; }

server {
    listen 443 ssl;
    server_name mall.example.com;          # 换成你的域名
    ssl_certificate     /path/fullchain.pem;
    ssl_certificate_key /path/privkey.pem;

    root /www/wwwroot/mall;
    index index.html;

    # 商城接口反代：前端请求你自己域名的 /api，转发到卡世界后端
    location /api/ {
        proxy_pass https://ksj_mall_api;
        proxy_set_header Host ym.ksjhaoka.com;   # 关键①：不带会落到目标默认站点
        proxy_ssl_server_name on;                # 关键②：HTTPS 上游必须开 SNI
        proxy_ssl_name ym.ksjhaoka.com;
        proxy_http_version 1.1;
        proxy_read_timeout 60s;
    }

    location / {
        try_files $uri $uri/ /index.html;        # SPA 路由回退，必须有
    }
}
```

**两个最容易漏的点**（漏了首页会空白或 502）：`/api` 反代里的 `proxy_set_header Host ym.ksjhaoka.com` 和 `proxy_ssl_server_name on`。

没有 HTTPS 也可以先用 80 端口跑通（把 ssl 两行去掉、listen 改 80），正式使用建议上 HTTPS（微信内打开需要）。

### 4.3 更简单的替代方案：纯反代（连文件都不用传）

如果你不想部署任何文件，可以只要一个 Nginx 配置：把你域名的**所有请求**反代到 `https://ym.ksjhaoka.com`（配置结构与 4.2 的反代段相同，`location /` 整体转发），访客流量的订单归属依然是 `tnTzlcsG66` 这家店。适合你完全不想碰文件、只要域名上线商城的场景。要这套配置可以找卡世界索取。

### 4.4 其他托管方式

| 方式 | 说明 |
|---|---|
| 宝塔面板 | 新建站点 → 上传部署包文件 → 按 4.2 加上 `/api` 反代和伪静态回退 |
| Vercel / Netlify | 上传部署包，并配置 rewrites：`/api/*` 代理到 `https://ym.ksjhaoka.com/api/*`，其余路径回退 `index.html` |
| APP 内嵌 | 部署包可直接放入 APP WebView 加载，`/api` 反代由你的接入层处理 |

### 4.5 部署验证

打开你的域名，**自动进入「号卡办理中心」商城首页，直接出现商品列表**（部署包已内置默认店铺跳转，不需要带任何参数）即部署成功。如果首页空白或接口 502，先检查 4.2 里标注的两个反代关键点。

3. **站点标题 / 图标**：替换 dist 根目录的 `favicon.ico`，修改 `index.html` 的 `<title>`。
4. **微信生态**：包内已内置支付中转页（`mpaybridge.html`）与微信校验文件（`MP_verify_xxx.txt`），微信内打开可直接使用，无需额外配置。

## 附录 A：接口全局约定（二次开发参考）

### 3.1 Base URL

```
https://ym.ksjhaoka.com/api
```

### 3.2 店铺码传递

所有接口必须携带 `store_id`：

- GET 请求：放 query string，如 `?store_id=tnTzlcsG66`
- POST 请求：放 form 表单 body，如 `store_id=tnTzlcsG66`

### 3.3 返回结构

所有接口统一返回：

```json
{
  "code": 0,
  "message": "操作成功",
  "data": {}
}
```

| code | 含义 |
|---|---|
| 0 | 成功 |
| 3 | 参数错误 |
| 其他 | 见响应 `message` 字段（中文错误描述） |

### 3.4 分页结构

列表类接口统一：

```json
{
  "code": 0,
  "data": {
    "list": [],
    "pagination": { "total": 63, "size": 5, "current": 1, "pages": 13 }
  }
}
```

请求分页参数：`current`（页码，默认 1）、`size`（每页条数，默认 30）。

### 3.5 图片 URL 规则（重要）

接口返回的图片字段有两种形态，前端需区分处理：

| 形态 | 示例 | 处理方式 |
|---|---|---|
| 相对路径 | `images/product/202608/01/xxx.png` | 拼接口域名前缀：`https://ym.ksjhaoka.com/` + 该路径 |
| 完整 URL | `https://kashijie-1318880227.cos.ap-guangzhou.myqcloud.com/images/...` | 直接使用 |

判断方法：以 `http` 开头直接用，否则拼域名前缀。

### 3.6 商品排序逻辑

商品列表接口默认排序规则（按访客 IP 自动定位省份）：

1. **访客所在省的专属卡**（非宽带）置顶
2. **全国可发货的卡**（归属地为"随机"/"本地归属地"）
3. **访客所在省的宽带**
4. 其他省份的产品

同层之内按店铺排序值（sort）升序。部署方如需自定义排序，可在前端拿到列表后自行重排。

### 3.7 金额说明

流量卡商城的商品为**办卡业务**，用户不在商城内支付费用（资费由运营商线下/激活后收取），商品接口中 `price` 字段固定为 0，资费信息以文字形式在 `tabs`、`set_meal`、`package_composition` 等字段展示。

### 5.11 下单办理（核心）

```
POST /api/index/order
```

**请求参数**

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| store_id | string | 是 | 店铺码 |
| goods_id | int | 是 | 商品 ID |

| province | string | 是 | 收货省 |
| city | string | 是 | 收货市 |
| district | string | 是 | 收货区/县 |
| address | string | 是 | 详细地址 |
| agreement | string | 是 | 已同意协议标识（协议卡必填） |
| captcha | string | 条件 | 图形验证码答案（`is_captcha=1` 时必填） |
| checkCode | string | 条件 | 验证码 key（5.9 接口返回的 key 回传） |
| set_meal | string | 条件 | 选中的套餐（`is_meal=1` 时必填） |
| option_phone | string | 条件 | 选号结果（`is_phone=1` 时必填） |
| phone_data | string | 否 | 号段数据 |

| pool | int | 否 | 商品池 ID（详情接口 `pool` 字段回传） |
| card_main | string | 条件 | 身份证正面照 URL（需先上传） |
| card_back | string | 条件 | 身份证反面照 URL |
| card_portrait | string | 条件 | 人像照 URL |
| first_source | string | 否 | 来源渠道标记 |
| url | string | 否 | 下单页面 URL（溯源用） |

**响应示例**

```json
{
  "code": 0,
  "message": "操作成功",

    "msg": "下单成功",
```

| 字段 | 说明 |
|---|---|

**下单流程建议**：

1. 详情页读取 `is_captcha / is_card_no / is_meal / is_phone / is_attribution` 决定表单字段

## 附录 E：注意事项与已知坑

1. **store/banner 的 `location` 必传**（0=首页 / 1=客服页），不传会返回服务端错误。
2. **store/config 返回平台默认客服**，与店铺码无关，不要拿它当店铺专属配置用。
3. **poster/goods（商品海报生成）** 依赖服务端店铺上下文注入，当前生产环境对调用方式敏感，非商城必需功能，建议自行用主图合成海报。
4. **排序**：商品列表默认按访客 IP 省份做四层置顶（本省专属 → 全国卡 → 本省宽带 → 其他），前端无需处理，但要知道列表顺序是动态的——不同省份的用户看到的前排商品不同。
5. **协议卡**：部分商品要求代理在后台同意协议并手动上架后才出现在列表中，属于正常业务规则；已下架/已下线的商品不会出现在任何接口返回中。
6. **order/detile 接口**（`POST /api/index/order/detile`）带固定校验 key，属于平台内部核对接口，第三方部署不需要使用。
7. 接口暂无限流公告，但请对商品列表等热点数据做前端缓存（建议 5 分钟级），避免高频重复请求。
